# 애플리케이션 계층
- 네트워크와 인프라의 존재 이유

## 1. 원리
- 네트워크를 통해 다른 종단 시스템과의 통신
- C나 파이썬, 자바와 같은 작성하여 종단 시스템에서 작동되어야 한다.

### 1-1 구조
- 클라이언트-서버 / P2P와 등과 같은 구조로 존재
- 클라이언트-서버는 서버가 알려진 고정 IP를 가지고 항상 동작해 있어 클라이언트가 필요할 때 언제든지 연결할 수 있게 한다. 
- P2P는 간헐적으로 연결된 호스트의 쌍으로 이루어져 상호작용을 하며 이용자가 늘어날 수록 망이 커지는 특징이 있다.

### 1-2 통신
- 각 종단 시스템은 네트워크를 통해 메세지를 교환하여 통신하며 이때 사용되는 프로그램을 프로세스라고 부른다.
- 프로세스는 소켓을 통해 메세지를 전달하거나 전달받는다.
  - 이 과정에서 필요한 것이 IP와 포트번호이다. IP는 메세지를 보낼 호스트의 주소이며 포트번호는 해당 호스트에서 실행되고 있는 프로세스의 소켓 번호이다.

### 1-3 이용 가능한 트랜스포트 서비스
- 애플리케이션 밑에서 작동하고 있는 트랜스포트 계층이 애플리켘이션 계층에게 제공할 수 있는 서비스는 신뢰적 데이터 전송, 처리율, 시간 보장, 보안이다.
  - 신뢰적 데이터 전송같은 경우에는 네트워크를 통해 이동하고 있는 데이터의 손실에 있어 신뢰적인 프로토콜(ex. tcp)을 사용하여 데이터의 신뢰성을 보장한다.
    - 이와 반대로 데이터의 손실을 일부 허용하는 서비스의 경우(ex. 화상통화) 비신뢰적인 프로토콜(ex. udp)을 사용할 수 있다.
  - 처리율이란 송신 프로세스가 수신 프로세스에게 전달할 수 있는 데이터의 비율을 나타내는 것으로 네트워크를 공유하는 인터넷 상에서 처리율은 계속해서 변한다.
    - 특정 프로세스는 처리율을 보장받기 바라며 이를 대역폭 민간 애플리케이션이라고 한다. 반대의 경우는 탄력적 애플리케이션이라고 한다.
  - 시간 보장이란 모든 데이터가 특정 시간내에 도착해야 하는 것을 보장한다. 이는 실시간으로 이루어지는 애플리케이션에서 중요하게 작동한다.
  - 보안은 송신자가 데이터를 보내면 해당 데이터를 암호화하여 데이터가 유출되더라도 안전하게 해야하며 수신자는 이 암호화된 데이터를 해독할 수 있어야 한다.
