## 과제와 질문

1. 인터넷 애플리케이션 5개와 이들이 사용하는 프로토콜
   - 웹(http), 전자메일(smtp), 디렉터리 서비스(dns), 비디오 스트리밍(dash), P2P(비트토렌트)
2. 네트워크 구조와 애플리케이션 구조 차이
   - 네트워크는 소켓을 통해 메세지를 전달하며 애플리케이션은 이 메세지를 통해 동작한다.
   - 애플리케이션 계층의 프로토콜은 네트워크 계층의 애플리케이션이다.
3. 두 프로세스 간의 통신에서 클라이언트와 서버인지 결정 짓는 것은?
   - 요청을 보내는 프로세스가 클라이언트고 응답을 보내는 프로세스가 서버이다.
4. P2P에서 서버-클라이언트 용어를 사용하는 이유
   - p2p 역시 요청과 응답 프로세스로 이루어져 있기 때문이다.
5. 어떤 호스트에서 실행되는 프로세스가 다른 호스트에서 수행되는 프로세스를 식별하기 위해 사용하는 정보
   - ip주소
6. 네트워크 애플리케이션에서 http 역할 및 그 외 구성요소
   - http는 애플리케이션에서 사용될 메세지를 정의한다. 덕분에 다른 프로세스와 요청, 응답이 가능하다.
7. 데이터 무손실과 시간에 민감한 애플리케이션
   - 인증번호
8. 트랜스포트 프로토콜이 제공할 수 있는 서비스를 네 가지 클래스로 분류
   -  신뢰, 처리, 시간, 보안
9. tls는 트렌스포트인지 애플리케이션인지? / tls를 통해 tcp를 향상시키려면 무엇을 해야하는 가?
- 애플리케이션 프로토콜 / 서버와 클라이언트에 tls코드가 존재해야 한다.
10. 핸드셰이킹 의미
  - 연결이 되었다.
11. 비상태 프로토콜이란? imap와 smtp는 비상태인가?
    - 비상태란 송신자의 데이터를 저장하지 않는 것을 의미 / imap와 smtp는 상태 프로토콜이다.
12. 웹사이트는 어떻게 고객 접속 기록을 유지하는 가? / 항상 쿠키를 사용해야 하는가?
 - 쿠키를 이용해 정보를 저장한다. / 캐시나 세션을 사용할 수 있다.
13. 웹 캐싱을 통해 어떻게 지연 시간을 줄이는 지? / 모든 객체의 지연시간이 감소인지 일부만 인지?
  - 캐싱된 서버가 기점 서버의 트랙픽을 대신 받아주기 때문에 지연 시간이 줄어든다. / 모든 객체의 지연시간이 감소한다. 왜냐하면 캐시를 통해 적중된 요청은 해당 요청에서 완료 되기 때문에 기점 서버로 가는 트래픽이 사라지게 된다. 이는 적중되지 않은 요청에 대해서도 대역폭을 보다 넓게 사용할 수 있기 때문에 지연시간의 감소가 나타나기 떄문이다.
15. http 포멧에는 어떤 제약이 있나? / smtp도 제약이 존재하는 가?
    - http는 통신을 위해 규격이 정해져 있으며 해당 규격을 토대로 요청, 응답이 정해져 있다. / smtp역시 from과 to의 형식을 가져야 한다.
